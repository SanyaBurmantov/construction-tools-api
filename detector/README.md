# ИИ-детектор (`detector/`)

Отдельный контейнер: оценивает вероятность, что русский текст написала
нейросеть. Им пользуются админка и сеошник (`/admin/ai-detector`), дальше —
обход сайтов.

```
backend /admin/ai-detector ──HTTP──► detector:8100  (Python, onnxruntime, CPU)
   ├─ безопасно скачивает страницу по URL (SSRF-защита, ai-detector/safe-url.ts)
   ├─ вынимает основной текст (ai-detector/page-text.ts)
   └─ хранит историю (AiDetectorCheck, 365 дней)
```

## API

| Метод | Что | Ответ |
| --- | --- | --- |
| `GET /health` | жив ли, какая модель | `{ok, model}` |
| `POST /analyze` `{text, fragments?}` | полный разбор | вероятность, вердикт, фрагменты, штампы, ритм, предупреждения |
| `POST /analyze/batch` `{texts: [...≤32]}` | только вероятности | для обхода каталога и сайтов |

С `DETECTOR_TOKEN` всё, кроме `/health`, требует `Authorization: Bearer …`.
Смещения (`start`/`end`) — в кодовых точках Unicode (Python); фронт
переводит их в индексы UTF-16.

## Как он устроен и почему так

**Модель.** `toiletsandpaper/russian-ai-text-detector-modernbert`: дообученный
`deepvk/RuModernBERT-small` (34,5 млн параметров, Apache-2.0) на русской части
корпуса [LLMTrace](https://arxiv.org/abs/2509.21269) — ~340 тысяч текстов людей
и моделей (GPT-3.5…o3, GigaChat, YandexGPT, DeepSeek, Qwen, Llama, Gemma,
Mistral…). Авторы приводят такие цифры на отложенной выборке: accuracy 0,963,
ROC AUC 0,993, людей принимает за ИИ в 3,4% случаев. На текстах до 50 слов
accuracy 0,94, от 150 слов 0,98. Версия и sha256 файлов закреплены в
`models.json`.

**Почему классификатор, а не «перплексия».** Методы без обучения
(DetectGPT, Fast-DetectGPT, Binoculars) считают, насколько текст «ожидаем»
для языковой модели. Хорошо они работают на моделях от 7 млрд параметров,
то есть нужна GPU или гигабайты RAM, а у прода 2,9 ГБ на всё. На моделях
меньше 3 млрд точность заметно падает (ICLR 2025: Fast-Detect на Phi-2 даёт
0,75 против 0,92 на Llama-3-8B). Классификатор на 35 млн параметров даёт на
русском ROC AUC 0,99 при 125 МБ памяти.

**Что показал замер здесь** (CPU, int8, 1 поток, окно 1024 токена): в
простое 125 МБ, пик около 330 МБ на тексте в 3000 слов с разбором на
фрагменты, на описание товара уходит 15–30 мс. int8 отличается от fp32 на
сотые доли (авторы: метка меняется у 1% текстов на пороге 0,5). Полная fp32 —
`MODEL_FILES=model.onnx` при сборке и `DETECTOR_MODEL_FILE=model.onnx`.
Первая проверка на наших текстах: Википедия ≈ 0%, тексты «под нейросеть»
≈ 100%, **описание с th-tool.by — 99,9%**. Шаблонный SEO-копирайтинг
поставщика модель считает машинным. Либо его и правда писал генератор, либо
это ложное срабатывание на жанре, которого не было в обучении. Поэтому перед
выводами о каталоге нужна калибровка на своих данных (ниже).

**Фрагменты.** Текст режется по предложениям на куски по 40–150 слов
(`text.py`), каждый оценивается отдельно, и в интерфейсе видно, какие абзацы
похожи на сгенерированные (как в «Антиплагиате»). Весь текст оценивается
отдельным прогоном: один пакет из длинного текста и фрагментов выравнивался
до 2000 токенов и съедал 4,8 ГБ.

**Штампы и ритм** (`signals.py`) — объяснения, а не вердикт. Правила такого
рода сами по себе плохо отличают человека от ИИ: у правил aiw-ru ROC AUC 0,62
против 0,99 у модели. Зато они показывают, *что* переписать: «играет
ключевую роль», «незаменимый помощник», «является», «таким образом»…
Разброс длины предложений (burstiness) и разнообразие слов (MATTR) —
подсказки, на которые опираются GPTZero и стилометрия.

## Чему верить (из исследований)

- Все детекторы обманываются перефразированием, ручной правкой и сменой
  настроек генерации (RAID, ACL 2024: 6 млн текстов, 12 детекторов;
  Krishna et al. 2023: перефраз снизил точность классификатора OpenAI с 30% до 15,6%).
- Ложные срабатывания на людях бывают от 0% до 100% в зависимости от детектора
  и стиля (2026: 135 тысяч пар отредактированных текстов, 13 детекторов). Чем
  «глаже» и шаблоннее человеческий текст, тем чаще его принимают за ИИ.
- Поисковики официально оценивают пользу текста, а не способ его написания.
  Google наказывает «масштабный контент» без ценности (scaled content abuse),
  кто бы его ни написал. Отдельный «ИИ-фильтр» Яндекса официально не
  подтверждён. Есть эксперимент агентства с 10 сайтами: авторские тексты
  через 8 месяцев были видны вдвое чаще, но через 4 месяца разрыв почти исчез.
- Отсюда правило: высокий процент — повод перечитать и переписать фактами, а
  не доказательство. Низкий — не гарантия «написал человек».

## Калибровка на наших данных (следующий шаг)

Пилот 29.10 — это готовая размеченная выборка: 200 товаров, у каждого текст
поставщика (`AiTaskItem.changes[*].old`) и текст DeepSeek (`.new`).
`POST /analyze/batch` по обеим колонкам покажет, как модель разделяет их
именно на карточках, и где ставить пороги для каталога. Без этого цифры по
описаниям товаров — ориентир, а не факт.

## Запуск

```bash
# локально, без Docker (нужен Python 3.12)
pip install -r requirements.txt
python scripts/fetch_model.py modernbert ./models
DETECTOR_MODEL_DIR=./models/modernbert DETECTOR_MODEL_FILE=model_int8.onnx python -m detector.server
python -m unittest discover -s tests -t .

# в составе стека
docker compose --profile detector up
```

**Прод.** Контейнер выключен, пока не включён профиль:
`COMPOSE_PROFILES=detector` в `.env.prod` (+ по желанию `DETECTOR_TOKEN`), затем
`docker compose -f docker-compose.prod.yml up -d detector`. Образ собирает
`.github/workflows/detector.yml` в `ghcr.io/…/construction-tools-detector:<VERSION>`.
Новая версия: поднять `detector/VERSION` и `DETECTOR_IMAGE_TAG` по умолчанию в
`docker-compose.prod.yml` вместе (CI проверяет). Пакет в ghcr должен быть
публичным, как backend и frontend, иначе серверу нужен `docker login ghcr.io`.

## Переменные

| Переменная | По умолчанию | Что |
| --- | --- | --- |
| `DETECTOR_MODEL_DIR` | `/models/modernbert` | папка модели (`inference.json`, токенизатор, ONNX) |
| `DETECTOR_MODEL_FILE` | `model_int8.onnx` | какой ONNX-файл грузить |
| `DETECTOR_MAX_TOKENS` | `1024` | окно; память растёт с квадратом окна |
| `DETECTOR_THREADS` | `1` | потоки onnxruntime |
| `DETECTOR_TOKEN` | — | Bearer-токен для всех запросов, кроме `/health` |
| `DETECTOR_PORT` | `8100` | |

Backend: `DETECTOR_URL` (`http://detector:8100`), `DETECTOR_TOKEN`,
`AI_DETECTOR_TTL_DAYS` (365).
