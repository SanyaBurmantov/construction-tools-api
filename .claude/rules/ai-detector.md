# ИИ-детектор и уникальность

Python-контейнер детектора, проверка страниц по URL, уникальность по шинглам, конкуренты, типограф.

- **ИИ-детектор** (09.11, `detector/` — отдельный Python-контейнер,
  `backend/src/ai-detector/`, `/admin/ai-detector`, открыт роли SEO). Русский
  классификатор ModernBERT (LLMTrace, ONNX int8 на CPU: 125 МБ в простое,
  ~330 МБ в пике) за JSON API `detector:8100`; backend сам скачивает
  страницу по URL (`safe-url.ts`: только публичные адреса, каждый редирект
  проверяется заново — иначе админ-инструмент читал бы `backend:8000` и
  `db`), вынимает основной текст (`page-text.ts`) и хранит историю
  (`AiDetectorCheck`, 365 дней). Ответ: вероятность, фрагменты по 40–150
  слов, штампы и ритм (объяснения, не вердикт). **Контейнер выключен
  профилем compose** (`COMPOSE_PROFILES=detector`): автовыкатка делает
  `up -d --no-build`, и образ, который нельзя скачать, откатил бы весь
  релиз. Образ версионируется отдельно (`detector/VERSION` =
  `DETECTOR_IMAGE_TAG` по умолчанию, CI сверяет; `.github/workflows/detector.yml`).
  Шаблонный текст поставщика (th-tool.by) модель оценила в 99,9% «ИИ»: до
  калибровки на парах пилота (текст поставщика / DeepSeek) цифры по
  карточкам — ориентир. Подробности и выводы исследования — `detector/README.md`.
  Калибровка 09.11 (1 152 пары пилота): текст поставщика от DeepSeek он не
  отличает (AUC ≈ 0,5) — инструмент «как увидит внешний детектор», не фильтр.
  **Уникальность** (`uniqueness.ts` чистый + `uniqueness.service.ts`, в том же
  ответе `report.uniqueness`): шинглы по 4 значимых слова, как text.ru, но
  **по основам** (`stem-ru.ts`, Snowball: «высокую/высокой» — одно слово;
  виды глагола и беглые гласные остаются разными). Сравнение: текст
  поставщика и похожие товары (если проверяется наш `/product/<slug>`), весь
  каталог **и тексты поставщиков** через GIN-индексы по описаниям
  (`uniqueness-sql.ts`, байт в байт с миграцией `description_fts`, первые
  4000 символов; 12 окон по 5 слов, `plainto_tsquery` без фраз — GIN отвечает
  без перепроверки, кандидаты по числу совпавших окон, решают шинглы; раньше
  был `LIKE`-перебор 4–7 с), страницы из `compareUrls` и **конкуренты**
  (`competitors.ts` + `competitors.service.ts`): поиск их собственных сайтов
  (`SiteSetting uniqueness.competitors`, правится на странице детектора,
  пусто = 21vek.by + shop.by; проверено с прода 09.11, mile.by отдаёт 403,
  Onliner — свою сводку, не текст) по бренду + коду модели из названия;
  ссылки-переходы агрегатора (`to.php?url=…`) разворачиваются в карточки
  самих магазинов (≤4, наш сайт пропускается). Для вставленного текста
  название товара вводится полем; без него у конкурентов не ищем. Бесплатно,
  без поисковика; поставщик и его адрес скрыты от роли SEO (`uniquenessForSeo`).
  **Типограф** (`frontend/app/utils/typograf.ts`) — только при выводе
  описаний товара, категории/посадочной и бренда; в базе исходный текст
  (поиск, уникальность, проверки ИИ). Названия, артикулы, модели через него
  не пускать — «10x40» должно находить «10x40».
