# ИИ-задачи (тексты товаров, категорий, брендов)

AiTask/AiTaskItem, раннер, провайдер, шаблоны, проверки до записи, исправление, уникальность, адреса, IndexNow.

- **AI-задачи** (`ai/`, **один экран `/admin/ai`** «ИИ-тексты» с табами
  `?tab=` товары | categories | brands | tasks | templates; старые
  `/admin/ai/{products,categories,tasks,templates}` — редиректы). Админ
  выбирает товары/категории/**бренды** (фильтры товаров: категория с
  поддеревом, бренд, поставщик, статус, наличие, пустое поле, «ИИ не писал
  поле X», новые за N дней, фото, «ни описания, ни характеристик», цена,
  сортировка — или «все по фильтру», который резолвится в id при создании),
  поля, шаблон и инструкции, и создаёт
  `AiTask` с `AiTaskItem` на каждую запись. Планировщик — `AiRunnerCron`
  (каждую минуту, одна задача, `AI_BATCHES_PER_TICK` пачек по `batchSize`
  записей в **одном** запросе: бесплатный ключ OpenRouter считает *запросы* —
  50 в сутки). 429 не валит записи, а ставит задаче `pausedUntil`; прочие
  ошибки — до 3 попыток на запись. Меняются **только текстовые поля**
  (`ai/ai-fields.ts`: name/описания/SEO) — цены принадлежат `PricingService`,
  идентичность — парсерам. Каждый item хранит `{field: {old, new}}`, откат
  возвращает старое значение только там, где поле всё ещё равно записанному ИИ.
  **`Product.aiLockedFields`**: поля, переписанные ИИ, `ProductIdentityService.save()`
  вырезает из `update` при перепарсинге — иначе суточный refresh вернул бы
  текст поставщика. Откат снимает блокировку только с полей, которые реально
  восстановил. Запись в сущность и в item — одна транзакция по свежему
  чтению (не по контексту двухминутной давности). Ответ модели чистится тем же
  `supplier-text.ts`. Модель задачи проверяет провайдер (см. ниже); 429 —
  пауза на весь ключ, а не на одну задачу; после ошибки пачки тик
  останавливается (не жжёт суточную квоту). **Провайдер** выбирает
  `ai/ai.client.ts`: задан `DEEPSEEK_API_KEY` — платный DeepSeek напрямую
  (OpenAI-совместимый API, модель `DEEPSEEK_MODEL`, по умолчанию
  `deepseek-flash` (V4.1 Flash; Pro — `deepseek-v4-pro`); в админке видно баланс, 402 «закончился баланс» — пауза
  ключа на час, а не провал записей); иначе `OPENROUTER_API_KEY` и только
  `:free`-модели с цепочкой запасных. Задача, созданная под другим
  провайдером, идёт на модели по умолчанию текущего. Оба ключа пусты =
  выключено. У `deepseek-flash` «рассуждение» включено по умолчанию и
  оплачивается как выход (~95% токенов короткого ответа) — клиент шлёт
  `thinking: disabled` (`DEEPSEEK_THINKING=enabled` вернёт).
  **Качество, до записи** (пилот 2026-10). Галочка «шаблоны» в мастере =
  `ai-templates.ts`: общие правила магазина (только факты из данных, полные
  названия, «оплата по безналу для организаций» в SEO-описании) + гайд на
  вид товара (21 шт.: крепёж, буры, круги, головки, аккумуляторный…; вид —
  по началу названия, затем по категории); такая задача делится на задачи
  по видам. Правила задачи стоят в system-сообщении — постоянный префикс,
  его DeepSeek считает по цене кеша. Ответ проходит `ai-validate.ts`: поле
  **не пишется** (старое остаётся, причина — `AiTaskItem.rejected`), если в
  нём число или латинское слово, которых нет в данных товара, неподтверждённое
  утверждение (наличие, гарантия, страна, «лучший»), телефон/ссылка/цена/
  разметка, слово из смешанных алфавитов, плохая длина; у названия — пропал
  бренд, код модели или число старого названия. Затем `ai-verify.ts`: второй
  запрос к модели проверяет смысл названия и краткого описания (ответ —
  `{ok:false, problem}` на поле; молчащий проверяющий = пачка повторяется,
  а не пишется непроверенное; `AI_VERIFY=false` выключает). Латиница и коды
  сравниваются со «сложенными» двойниками (М/M, х/x/×) — поставщик пишет
  «М10х12х40» кириллицей, модель латиницей. Описание, почти совпадающее с уже записанным
  в той же задаче (варианты линейки), помечается в `AiTaskItem.warnings`.
  **Справка до записи, исправление вместо отказа** (`ai-brief.ts`, 09.11):
  тексты, которые задача переписывает, идут модели как `sourceShort` /
  `sourceDescription` — источник фактов, не черновик под именем поля; у
  варианта линейки — `line` (`thisVariant` и соседи, размеры из имён как у
  переключателя `variants.ts`, только различающиеся; числа соседей не
  становятся фактами карточки — валидатор смотрит на её данные). Поле, не
  прошедшее проверки (`validateAnswer` + уникальность), модель переписывает
  **один раз в том же диалоге** (`checkAndRepair`: причина и цитаты
  скопированных кусков, `repairMessage`; префикс — кеш DeepSeek), и только
  потом — отказ. Затем проверка смысла (`secondOpinion`) на итоговом тексте.
  **Уникальность** (`ai-rewrite-checks.ts`, `UniquenessService.forRewrite`):
  шинглы по основам против прежнего текста и текстов поставщика товара, ниже
  `AI_MIN_UNIQUENESS` (50%, 0 = выкл.) — отказ. «Похожие описания» в задаче —
  те же шинглы (≥ 60% покрыто уже записанным, предупреждение); поиска по
  каталогу и конкурентов в задачах нет — это страница детектора. Вероятность
  детектора хранится (`AiTaskItem.quality`), не фильтр.
  **Замер 09.11** (30 разных карточек, по 2 прогона, тот же предпросмотр):
  отказов 16 → 0, текстов < 50% 11 → 0, исправлений ~1 карточка из 6,
  похожесть вариантов (среднее) 70 → 61%, медиана уникальности полного
  описания 73,7 → 76,2% (в пределах разброса прогонов ±4), входных токенов
  +12%. Главное даёт исправление, а не перенос текста в `source*`.
  Предпросмотр делает ровно то же, что задача (вместе с исправлением).
  **Стиль против детектора** (замер 09.11, те же 30 карточек): стоп-лист
  штампов + ритм + конкретика в правилах товара не сдвигают детектор
  (медиана полного описания 0,996 → 0,982; температура 0,8 — 0,988 и больше
  отказов, оставлена 0,3), но уникальность 75 → 89%, похожесть вариантов
  58 → 24%, штампов 19 → 0. Правила оставлены ради текста, не ради детектора. Токены копятся в `AiTask`;
  `AI_MIN_BALANCE` («36.4» или «36.4 CNY») останавливает раннер ниже порога
  баланса одной валюты (DeepSeek отдаёт CNY и USD рядом — не складывать);
  баланс не прочитался — тоже стоп.
  **Новое название — новый адрес только у черновика**
  (`aiMayMoveProductUrl`, 09.11): товар, который хоть раз был на сайте, уже
  в sitemap и отправлен в IndexNow, а переезд обнуляет индексацию на недели
  даже с 301 (пилот 29.10: из 157 переехавших через неделю в индексе 27,
  у оставшихся на месте ~44%). Узнать «в индексе ли» для 100k адресов нельзя
  (Search Console — 2 000 проверок в день), поэтому «был в продаже» =
  «известен поисковикам»: меняется только название. У `DRAFT` slug строится
  из нового названия (`products/product-slug.ts`, ≤ 90 символов), со старого
  — 301 (`ProductRedirect`), в `changes.slug` — откат возвращает адрес.
  Парсер slug существующего товара не пишет.
  **Адрес двигается один раз**: `slug` в `aiLockedFields`/`lockedFields`
  значит «адрес уже наш» (после ИИ или ручной правки в админке) — повторный
  прогон меняет название, но не URL.
  Витрина берёт `seoTitle`/`seoDescription` товара, только если их написали
  мы (ИИ или админ — поле в `aiLockedFields`/`lockedFields`): API отдаёт
  `null` вместо текста поставщика. Текст категории — под сеткой товаров
  (сверху первый абзац в две строки), только на первой странице.
  **Поисковики**: `Product.contentUpdatedAt` — когда менялся текст/адрес
  страницы (ИИ, админ, или поставщик переписал незакреплённый текст), это
  `lastmod` в sitemap (`updatedAt` двигает ежедневный парсинг). `seo/indexnow.service.ts` шлёт изменённые адреса
  Яндексу (IndexNow, очередь `IndexNowUrl`, раз в 10 мин в воркере); ключ
  `INDEXNOW_KEY`, файл `/<ключ>.txt` отдаёт фронт (`NUXT_INDEXNOW_KEY`).
  **Весь каталог тоже идёт в IndexNow** (05.11, из Яндекса было 2 визита
  против 133 из Google): товар, который `publishIfReady()` только что
  выставил в продажу, уходит в очередь сразу, а `IndexNowSeedService`
  (воркер, 05:11) один раз проходит каталог — в первую ночь главные
  страницы, видимые категории с предками и бренды, дальше по
  `INDEXNOW_SEED_PER_DAY` (10 000) товаров за ночь по id; курсор
  `SiteSetting indexnow.seed.cursor`, конец — `indexnow.seed.doneAt`.
  **Яндекс.Вебмастер**: gost.by добавлен через API 05.11 в аккаунт владельца
  счётчика Метрики, права подтверждены мета-тегом
  `YANDEX_WEBMASTER_VERIFICATION` в `nuxt.config.ts` — не удалять.
  **Всё видно и правится в админке** (`/admin/ai/templates`, «ИИ ·
  Шаблоны»): общие правила товаров/категорий и гайды по видам
  (`AiTemplateTextsService`, `SiteSetting ai.text.*` поверх кода; задача
  сохраняет свой текст при создании), список проверок (`AI_CHECKS`),
  промпт второй проверки, «показать запрос» по товару (`POST
  /admin/ai/templates/explain`, без вызова модели) и живой предпросмотр.
  Для сеошника — справочник полей (где видно на сайте, длина) и
  **библиотека шаблонов** (`AI_PRESETS` в `ai/ai-scaffolds.ts`, свои —
  `AiPrompt` с `fields` + `fieldTexts`): шаблон = поля + общая инструкция +
  **инструкция на каждое поле**, с [местами для заполнения] (мастер не
  запустит задачу, пока скобки не заменены).
  **Запрос собирается из блоков** (`instructionBlocks`/`composeInstruction`,
  мастер показывает их по «Как соберётся запрос»): «Формат ответа»
  (`formatBlock`, фиксирован в коде) → правила магазина (+ гайд по виду) →
  «Требования этой задачи» (общая + по полям, **важнее правил** при
  противоречии) → данные записи. Своё задачи хранится отдельно в
  `AiTask.promptParts`. **Фразы в кавычках от двух слов** из этих
  требований (`ai/ai-phrases.ts`) проходят дословно: очистка от рекламы
  поставщика (она режет «купить … в Минске») и `ai-validate.ts` смотрят на
  текст без них, проверяющей модели их называют — иначе «купить в Минске по
  низким ценам» сеошника не доходило до карточки. Фразы берутся только из
  требований задачи, не из правил (там в кавычках запреты).
  **Бренды**: `AiEntity.BRAND`, поля description/seoTitle/seoDescription
  (имя — идентичность, не трогается), правила `BRAND_BASE_RULES`
  (`ai.text.brand-rules`), данные — категории и товары бренда на витрине;
  `/brand/:slug` берёт SEO бренда, если оно не равно имени (парсер сеет имя),
  и выводит «О бренде» под категориями.
  Скрипт пилота: `scripts/ai-pilot.mjs select|create|report` (подбор 300
  карточек + контрольная группа, этапы — каждый создаётся один раз, отчёт).
  Сквозной тест на настоящей базе: `src/ai/ai-pipeline.db.spec.ts`
  (пропускается без `AI_PIPELINE_TEST_DATABASE_URL` на базе `*_test`).
