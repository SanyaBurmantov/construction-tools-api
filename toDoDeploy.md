# To do при деплое: почта (SMTP hoster.by)

Что появилось в коде: письмо о каждом новом заказе на `MAIL_ADMIN_TO` и
письмо с подтверждением e-mail при регистрации (`/verify-email?token=…`).
Без настроек ниже отправка просто выключена — сайт работает, писем нет.

## 1. Сменить пароли ящиков

Пароли `support@`, `admin@`, `manager@gost.by` прошли через мессенджер —
сменить в панели hoster.by. В репозиторий их не писать.

## 2. Дописать в `.env.prod` на сервере

```
SMTP_HOST=mailbe03.hoster.by
SMTP_PORT=465
SMTP_USER=support@gost.by
SMTP_PASSWORD=<новый пароль от support@gost.by>
MAIL_FROM="gost.by <support@gost.by>"
MAIL_ADMIN_TO=admin@gost.by
PUBLIC_ORIGIN=https://gost.by
```

- `MAIL_ADMIN_TO` — можно несколько через запятую: `admin@gost.by,manager@gost.by`.
- `PUBLIC_ORIGIN` — обязательно настоящий домен, иначе ссылка в письме подтверждения поведёт не туда.
- `MAIL_FROM` — отправитель должен совпадать с ящиком `SMTP_USER`.
- Если 465 не подключается — поставить `SMTP_PORT=587`.

## 3. Задеплоить и перезапустить backend

Миграция `20261015120000_email_verification` (колонка `User.emailVerifiedAt`
и таблица `EmailVerification`) применится сама при старте контейнера
(`prisma migrate deploy`).

## 4. Проверить

- [ ] В логе backend есть строка `SMTP mail enabled via mailbe03.hoster.by as support@gost.by`
      (а не `SMTP mail disabled …`).
- [ ] Тестовый заказ → письмо «Новый заказ №…» пришло на `admin@gost.by`.
- [ ] Тестовая регистрация → письмо «Подтверждение регистрации на gost.by» пришло,
      ссылка открывает `/verify-email` и пишет «E-mail … подтверждён».
- [ ] В личном кабинете у нового аккаунта пропала плашка «E-mail не подтверждён».
- [ ] Если писем нет — смотреть в логе backend строки `Mail send failed …`.

## 5. DNS: DKIM и DMARC (чтобы письма не падали в спам)

Сейчас в DNS gost.by есть только SPF. Без DKIM Gmail и Mail.ru часто кладут
письма в спам, и письма подтверждения страдают первыми.

- [ ] Включить DKIM для gost.by в панели hoster.by (добавит TXT-запись).
- [ ] Добавить TXT-запись `_dmarc.gost.by` со значением `v=DMARC1; p=none`.

## Справка

- Подтверждение мягкое: неподтверждённый пользователь всё равно входит и
  оформляет заказ. E-mail при регистрации теперь обязателен (или логин = e-mail).
- Срок жизни ссылки — `EMAIL_VERIFICATION_TTL_HOURS` (по умолчанию 48).
- Повторная отправка письма из кабинета — не чаще 3 раз в час.

# To do при деплое: ИИ-задачи в админке (OpenRouter)

Что появилось в коде: разделы «ИИ · Товары», «ИИ · Категории» и «ИИ · Задачи»
(`/admin/ai/*`). Пользователь выбирает записи, поля и промпт, а планировщик раз
в минуту отправляет их в OpenRouter и обновляет тексты. Без ключа раздел
открывается, но задачи не выполняются.

## 1. Дописать в `.env.prod` на сервере

Файл `/opt/construction-tools/app/.env.prod`:

```
OPENROUTER_API_KEY=
OPENROUTER_MODEL=google/gemma-4-31b-it:free
```

- Ключ должен оказаться в `.env.prod` **до** деплоя: compose читает его при `up`.
  Если ключ добавили позже, перезапустите backend:
  `docker compose --env-file .env.prod -f docker-compose.prod.yml up -d backend`.
- В репозиторий ключ не писать: этот файл и `backend/.env` в `.gitignore`.
- Необязательные настройки: `AI_BATCHES_PER_TICK` (по умолчанию 3 — сколько пачек
  обрабатывается за минуту) и `AI_RUNNER_ENABLED=false` (выключает планировщик).

## 2. Закоммитить и выкатить

Сейчас изменения не закоммичены. Коммит в `master` → push → PR `master → prod`
→ merge. Таймер `construction-tools-deploy` на сервере сам соберёт стек и при
неудаче откатится.

Миграция `20261015180000_ai_tasks` применится при старте контейнера. Она
только добавляет: таблицы `AiPrompt`, `AiTask`, `AiTaskItem` и колонку
`Product.aiLockedFields` с пустым значением по умолчанию.

## 3. Проверить

- [ ] В логе backend **нет** строки `AI tasks disabled — set OPENROUTER_API_KEY`.
- [ ] `/admin/ai/products` показывает «OpenRouter подключён» и остаток лимита
      «Бесплатных запросов сегодня: N из 50».
- [ ] Отметить 1–2 товара → «Создать задачу ИИ» → поле «SEO description» →
      «Проверить на …»: появились «было → стало».
- [ ] Создать задачу. В течение 1–2 минут в «ИИ · Задачи» она становится
      «Готово», а в «Результатах» видны изменения.
- [ ] Открыть товар на сайте: текст новый (ISR-кэш страницы товара держится до 15 минут).
- [ ] Нажать «Откатить» у задачи: текст вернулся к прежнему.
- [ ] Если задача висит — смотреть в логе backend строки `AI task …` и `AI runner failed`.

## Справка

- **Лимит.** Бесплатный ключ = 50 запросов к `:free`-моделям в сутки. В одном
  запросе уходит пачка записей (по умолчанию 5), то есть около 250 товаров в
  сутки. Когда лимит кончился, задача ждёт его сброса («Лимит модели —
  продолжит …»), а записи не помечаются ошибочными. Больше лимит — только на
  платном аккаунте OpenRouter.
- **Модель по умолчанию.** Если она недоступна, OpenRouter сам переключается на
  запасные бесплатные (`nemotron-3-super`, `openrouter/free`). Ответ занимает
  10–60 секунд.
- **Перепарсинг не затирает тексты ИИ.** Переписанные поля закрепляются, и
  парсер их больше не трогает. Откат задачи снимает закрепление.
- **Переименование категорий.** Не давайте ИИ переименовать категорию так,
  чтобы имя совпало с соседней: ночной нормализатор склеивает одноимённые
  категории.
